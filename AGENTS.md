# AGENTS.md — gcs-versioning-bot

## Purpose

GitHub Composite Action for rule-driven automatic semantic versioning of Smart Contract and software artifacts. Reads versioning and branch-packaging rules from pre-generated YAML importer files, queries JFrog Artifactory for existing versions, and computes the next semantic version based on branch type, Jira ticket data, and commit messages.

## Architecture Patterns

- **Importer-driven configuration** — all versioning rules are read from flat env files generated by `gcs-yaml-importer`. This decouples config from action logic.
- **Branch-type detection** — inspects `GITHUB_REF_NAME`, `GITHUB_HEAD_REF`, and `GITHUB_BASE_REF` to determine branch type (feature, release, hotfix, default, PR).
- **Artifactory version query** — uses JFrog CLI to fetch existing artifact versions, then applies semver bump rules.
- **Jira enrichment** — optional; if enabled in rules, queries Jira ticket status to append pre-release labels.
- **Sed-based importer migration** — automatically upgrades legacy `::set-output` format in importer files to the modern `>> $GITHUB_OUTPUT` format.

## Key Abstractions

- **Importer files** — flat bash env files where each YAML leaf node becomes `YAML_PATH_UNDERSCORE_KEY=value`. Must be generated by `gcs-yaml-importer` before calling this action.
- **`BUILD_GH_BRANCH_NAME`** — the normalised branch name used throughout versioning logic; extracted from `GITHUB_REF_NAME` or `GITHUB_HEAD_REF`.
- **`steps.final-version`** — the step that produces all three outputs (`full-version`, `new-version`, `old-version`).
- **`config/general.ini`** — fallback defaults loaded before importer file values are applied.

## Agentic Task Guidance

- ✅ Safe: Reading `action.yml` to trace the step sequence; reading `config/general.ini`; running unit test workflows; adding debug logging via `debug: "true"`.
- ⚠️ Review: Modifying the importer file parsing (`inject_config_vars.sh`); changing the branch-type detection logic; adding new version bump strategies; changing Artifactory query patterns.
- ❌ Avoid: Passing `branch-name` or `rebase-branch-override` in production (testing-only overrides); committing Artifactory or Jira credentials; skipping the credential validation step.

## External Dependencies & Integrations

- **JFrog Artifactory** — queried for existing artifact versions to determine the next version number.
- **Jira** — optional; fetched for ticket metadata to enrich pre-release version labels.
- **`gcs-yaml-importer`** — prerequisite; must run before this action to generate the importer files.
- **`partior-sec-eng/controller-generic-pipelines`** — provides shared CI pipeline templates.

## Common Pitfalls

- Both `versioning-rules-importer-file` and `branch-packager-rules-importer-file` are required and must exist on the runner — missing files cause an early exit with error.
- The sed migration (`::set-output` → `>> $GITHUB_OUTPUT`) modifies the importer files in-place — if the same file is used by multiple steps, this is idempotent but may cause confusion during debugging.
- `debug: "true"` outputs all resolved config variables to the workflow log, which may include sensitive values — use only in non-production runs.
- Jira versioning must be explicitly enabled in the versioning rules YAML; simply providing `jira-username`/`jira-password` without enabling it in the rules has no effect.
