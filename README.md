# gcs-versioning-bot

> GitHub Composite Action for rule-driven automatic semantic versioning of Smart Contract and general software artifacts, integrating with JFrog Artifactory and Jira.

## Overview

`gcs-versioning-bot` reads versioning and branch-packaging rules from YAML importer files (generated by [`gcs-yaml-importer`](../gcs-yaml-importer/)) and computes the next artifact version based on:

- The current Git branch type (feature, release, hotfix, main, PR, etc.)
- Existing artifact versions queried from JFrog Artifactory
- Optional Jira ticket information (for pre-release label enrichment)
- Consolidated commit messages (for conventional-commit parsing)

It outputs the new full version string, the version-only string, and the previous version for downstream steps (tagging, packaging, publishing).

## Usage

```yaml
- uses: partior-libs/gcs-versioning-bot@main
  with:
    jfrog-token: ${{ secrets.JFROG_TOKEN }}
    versioning-rules-importer-file: versioning-rules.env
    branch-packager-rules-importer-file: branch-packager-rules.env
```

## Inputs

| Input | Description | Required | Default |
|-------|-------------|----------|---------|
| `artifactory-username` | Artifactory username | No | `""` |
| `artifactory-password` | Artifactory access token / password | No | `""` |
| `jfrog-token` | JFrog Platform token (preferred over username/password) | No | `""` |
| `artifactory-base-url` | Artifactory base URL | No | `https://partior.jfrog.io/artifactory` |
| `jira-username` | Jira username (required if Jira versioning source is enabled) | No | `""` |
| `jira-password` | Jira password / API token | No | `""` |
| `jira-base-url` | Jira base URL | No | `https://partior.atlassian.net` |
| `branch-name` | Override branch type name (testing only) | No | `""` |
| `rebase-branch-override` | Override rebase branch (testing only) | No | `""` |
| `versioning-rules-importer-file` | Flat env file from `gcs-yaml-importer` containing versioning rules | Yes | `""` |
| `branch-packager-rules-importer-file` | Flat env file from `gcs-yaml-importer` containing branch packaging rules | Yes | `""` |
| `consolidated-commit-msg` | Consolidated commit messages from `git log` for conventional-commit parsing | No | `""` |
| `artifact-type` | Artifact type to query from Artifactory | No | `""` |
| `debug` | Enable verbose debug logging | No | `false` |

## Outputs

| Output | Description |
|--------|-------------|
| `artifact-full-version-name` | Full version string including artifact name (e.g. `my-service-1.2.3-rc.1`) |
| `artifact-version-name` | Version-only string (e.g. `1.2.3-rc.1`) |
| `artifact-old-version` | Previous version before this run (e.g. `1.2.2`) |

## Prerequisites

- Either `jfrog-token` **or** both `artifactory-username` + `artifactory-password` must be set.
- Importer files must be generated by `gcs-yaml-importer` and made available on the runner before this action is called.
- If Jira versioning is enabled in the rules, `jira-username` and `jira-password` are required.

## Examples

### Full versioning pipeline

```yaml
jobs:
  version:
    runs-on: ubuntu-latest
    outputs:
      new-version: ${{ steps.versioning.outputs.artifact-version-name }}
    steps:
      - uses: actions/checkout@v4

      # Generate importer files first
      - id: import-versioning
        uses: partior-libs/gcs-yaml-importer@main
        with:
          yaml-file: config/versioning-rules.yaml
          query-path: .artifact-auto-versioning

      - id: import-branch
        uses: partior-libs/gcs-yaml-importer@main
        with:
          yaml-file: config/branch-packager.yaml
          query-path: .branch-packager

      - id: versioning
        uses: partior-libs/gcs-versioning-bot@main
        with:
          jfrog-token: ${{ secrets.JFROG_TOKEN }}
          versioning-rules-importer-file: ${{ steps.import-versioning.outputs.importer-filename }}
          branch-packager-rules-importer-file: ${{ steps.import-branch.outputs.importer-filename }}

      - run: echo "New version: ${{ steps.versioning.outputs.artifact-version-name }}"
```
